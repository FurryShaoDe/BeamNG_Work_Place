# LapLog Project

LapLog 的两部分放在同一个文件夹里，方便一起维护：

```
LapLog_Project/
  LapLog/            BeamNG.drive 圈速记录模组（游戏内 HUD app + vehicle controller）
  一键启动查看器.bat  本机启动分析台并打开浏览器
  LapLog_Viewer/     本地圈速分析台（Python 脚本 + 浏览器可视化；浏览只读，删除记录会写 _trash）
```

## 模组：LapLog/

复制 `LapLog/` 到 BeamNG 用户目录的 `mods/unpacked/LapLog/`（或打包成 zip），进游戏在 UI Apps 里添加 **LapLog**。
行为、数据格式与目录说明见 `LapLog/README.md`。

### 计时精度与采样率（结论速览）

- **采样率**：面板可选 20/30/50/100 Hz，默认 50。采样挂在物理步上（累加器一次一采、不补点），`t` 轴是物理步累加时间。
  实测（63.7 s 的真实圈）：50→100 Hz 收益 <1%（把 50 降到 25 Hz 也只动 ~1%），代价是文件 630 KB→1.26 MB、
  查看器解析 20→40 ms、载荷 264→528 KB、绘制点数翻倍。**只有开始记录 Tier 1 瞬态列（轮胎滑移/接地/悬架行程/碰撞）时才值得开 100 Hz**，
  加低频量（温度/油量/转向角/四轮载荷/车身姿态）50 Hz 足够。
- **圈速精度**：过门检测跑在渲染帧（`updateGFX`），成绩取那一刻的累加时间、**不做过门时刻插值**（插值比例只用于横向/垂直校验）。
  不过起点滞后与终点滞后同源、大部分互相抵消：实测三圈偏差 **−1.8 / +0.3 / +1.5 ms**；最坏情况 = 一帧（60 fps 约 17 ms，
  掉帧更大）。所以两圈成绩差在 ~20 ms 以内时，别当成真实差距。
- 以上行为同源于参考模组 Ghost Racer Enhanced（LapLog 由它派生，逐行同构）；差别是它在官方比赛/Time Trial/Quick Race 模式
  不自己计时，改读游戏官方的 `historicTimes[].lapTime`（`raceControlled` 分支 + `finishRaceLap`）——LapLog 没有这个集成。
- **暂缓（用户 2026-10-04 决定先不做）**：① 给 approach latch 记 `elapsed` 时间戳 + 用 `amount` 反推过门时刻（把最坏情况压到亚毫秒）；
  ② "起点门与录制起点对不上"的旧记录校验（老版"设置起点立刻开录"可能留下的短圈）。完整数据、判据与实测表见
  `LapLog/README.md` 的 *Timing precision* / *Sample rate* 两节。

## 分析台：LapLog_Viewer/

事后分析工具：读取游戏写出的圈速存档（`<BeamNG 用户目录>/lapLogs/`），在浏览器里看轨迹、通道曲线、
多圈叠加、ΔT，并按现实时间播放某一圈。**浏览与分析只读、不需要游戏在运行**；只有主动点“删除”
才会写入 lapLogs——样本与旧清单先移入 `lapLogs/_trash/` 回收站，可手工恢复。

启动方式（二选一）：

```
双击  一键启动查看器.bat          # 自动开服务 + 开浏览器，端口 8010
或：  python LapLog_Viewer/server.py [--port 8010] [--root "…\BeamNG.drive\current"]
```

`--root` 可以给 BeamNG 用户目录、版本目录，或 `lapLogs` 目录本身；不给则自动探测
`%LOCALAPPDATA%\BeamNG\BeamNG.drive\current`。

⚠️ **改过 `LapLog_Viewer/` 里的代码后必须重启查看器**：静态文件（html/js/css）是每次请求现读磁盘的，
但 API 代码（通道表等）在进程启动时就固定了——只刷新浏览器会得到"新前端 + 旧接口"，新曲线会静默缺席。
页面检测到版本不一致时会在顶部与面板里提示重启（`server.py` 的 `VIEWER_CODE_VERSION` ↔ `web/app.js` 的
`SERVER_CODE`，改通道或返回结构时两边一起加）。

### 界面

- 左栏：地图 → 起点 → 圈列表（勾选叠加、点行切主圈、筛选完整/未完成/手动、CSV 导出、✕ 删除）。
  另外单列一组 `vehicles/<车辆>`（标注「按车辆存放」）：模组在**没有活动起点**时会把记录写进
  `lapLogs/vehicles/<车辆>/`（默认回放库，手动录制常落在这里），这类记录没有地图/起点信息，
  轨迹图不画起点门、也没有 PB，其余（曲线/播放/CSV/删除）与普通起点完全一样。
- 轨迹图：滚轮缩放、拖动平移、悬停读位置；起点门绿虚线、终点门黄虚线；着色可切 按圈/速度/油门刹车/档位
- 通道曲线：速度、油门刹车、档位、G 值（横向/纵向）、悬架载荷、车身姿态，x 轴可切时间或距离，共享游标
- 悬架载荷 / 车身姿态（模组 format 4，LapLog 1.0.2 起记录）：每圈四条线 = 前左/前右/后左/后右的垂直接地载荷（kN，
  实线/虚线/点线/点划线区分）；姿态图三条 = 侧倾（实线）/俯仰含地形（虚线）/俯仰去地形（点线）。
  旧档案没有这些列，服务端会把通道标 `available:false`，面板留空而不是画一条零线；游戏内圈列表也会显示「含载荷」标记。
- 悬架示意（自绘 `web/suspension.js`，播放/悬停时实时形变）：
  - 左「正视图」= 前轴横截面（左 FL / 右 FR，看到的是**胎面/胎花** —— 轮胎画成带 V 形沟槽的圆角矩形、底面平贴地面），
    右「侧视图」= 整车侧面（前 → 后，看到的是**轮毂** —— 圆 + 5 根辐条 + 中心盖）；
  - 弹簧长度、车身姿态由**录到的**四轮载荷 + 侧倾/俯仰驱动：每角「压缩量」= (当前载荷 − 本圈中位数) ÷ 本圈最大偏离，
    归一化到 −1..1 → 该角车身上下移动（压缩侧弹簧变短），所以一眼能看出哪个角在压、哪个角在抬；
    **没有弹簧刚度，所以不标毫米**，读数给绝对 kN 与 ΔN；「形变放大 ×1/×2/×4」控制视觉幅度（默认 ×2）；
  - 「反转倾斜方向」开关：引擎 `getRollPitchYaw()` 的正负号没有权威文档，觉得方向拧了就直接勾上；
  - 车轮载荷 < 15% 静态值时画成**离地**（虚线接地 + 「离地」标记）；每角还有一条相对静态的形变条（红=压 / 青=弹）；
  - 底部：前后载荷分配条 + 轴间转移（N）、侧倾/俯仰/去地形俯仰/坡度/速度、油门刹车小条，右下是带 1 秒拖尾的 G-G 圆盘；
  - **倾斜来源**（面板头选择，默认「悬架载荷」）：`悬架载荷` = 车角高度纯由四轮载荷决定（不掺地形）；
    `实测−地形` = 叠实测姿态但俯仰减掉地形坡度；`实测世界姿态` = 原样叠实测 roll/pitch。
    ⚠️ 记录的 roll/pitch 是**世界姿态**：实测一条 223 s 山道圈（ks_nord）里 `corr(俯仰, 地形坡度) = +0.97`，
    与纵向加速度只有 −0.10、与油门 0.01、与刹车 0.07 —— 俯仰几乎完全被坡道主导，**拿它直接画悬架就会"油门刹车对不上倾角"**，
    所以默认只用载荷。服务端为此新增两个派生通道：`grade`（地形坡度 %，沿行进方向 25 m 前瞻窗口）与
    `pitch_road`（俯仰去地形 = 实测 − 坡度角）；车身姿态图里那条**点线**就是它，虚线和它的差距 = 地形贡献。
- 播放：按现实秒（1×）播放主圈——轨迹图上的黄箭头是**车头朝向**，曲线游标与读数同步跟随；
  可暂停、拖动进度、切 0.25×–4×、勾选视图跟随/循环；空格 = 播放/暂停，←/→ = ∓1 秒（Shift ±5 秒）
- 朝向 / 滑移：可勾选「车头指引线」（黄实线）与「行进方向线」（青虚线，由相邻采样点的位置差求得），
  两线夹角即**滑移角**（画成弧线 + 车旁度数，读数里也有「滑移 ±x.x°」，|角度| ≥ 5° 变黄、≥ 15° 变红）。
  线长按米数可选（20/40/60/100 m），缩得较小时会保底约 55 px 以便看清。
  ⚠️ 角度是录制的**车体前向**（`obj:getDirectionVector()` 的水平投影），不是速度方向，也不是实时值——
  所以「箭头与实际行驶方向不一致」本身就说明车在推头/甩尾；挂倒挡时箭头仍指车头前方。
- 视图跟随：勾选后播放时轨迹图把车保持在画面中部（死区跟随，全览时也生效），曲线 x 轴同步平移；
  手动缩放/平移地图后跟随继续以新缩放比例工作，取消勾选即可自由查看
- ΔT：以最快圈为参考、按距离对齐的真实时间差
- 汇总：圈速（来自模组计时，见上：实测偏差 ±2 ms 量级、最坏一帧）、距离、最高/平均速、
  全油门/刹车/滑行占比、采样点、车型
- 采样率无关：x 轴用记录里的 `t`，20/30/50/100 Hz 的圈都能直接读；派生通道（航向/距离/纵向加速度/横向 G/地形坡度/俯仰去地形）都在服务端按同一套公式算
- 通道可用性：样本列是"尾部追加"的，服务端按每圈真实的列数给每个通道标 `available`，所以新加的列在旧记录上显示为空、而不是零线；派生通道永远可用

### 删除记录

圈列表每行的 ✕ 会删除该圈记录（先弹确认）。删除规则与游戏内一致：

- 库内记录：从 `laplog.save.library.json` 移除条目，样本 JSON 与旧清单移入 `lapLogs/_trash/`；
- 清单外样本：只把样本文件移入 `_trash`；
- `laplog.save.json`（主档案）与 `.time` 侧车按剩余最快圈重写，避免游戏内显示已删成绩；
  没有计时圈时两者也一并移入 `_trash`。

注意：删除时要**退出游戏**（或至少不要让游戏加载着该起点），否则游戏可能按内存里的库回写。
需要恢复时，把 `_trash/` 里的样本 JSON 拷回 `<起点>/laplog.save.ghosts/`，并把
`_trash/*_entry.json` 里的 `entry` 对象补回 `laplog.save.library.json` 的 `ghosts` 数组即可。

### 接口（浏览只读；delete 会写 lapLogs）

| 端点 | 说明 |
| --- | --- |
| `GET /api/catalog` | 地图 → 起点树（含各起点圈数、PB、清单外样本数）；旧版按车辆库单列为 `vehicles/<车辆>`（`legacyVehicle: true`） |
| `GET /api/laps?start=<group>/<level>/<id>` | 圈清单（manifest 内 + 清单外样本） |
| `GET /api/lap?start=…&id=<gid>` | 单圈样本，按通道展开（含派生通道） |
| `GET /api/export.csv?start=…&id=…` | 单圈宽表 CSV（MoTeC 式，供外部工具导入） |
| `POST /api/rescan` | 清解析缓存（跑完新圈点"重新扫描"即可） |
| `POST /api/delete?start=…&id=…` | 删除一条圈速记录（样本移入 `_trash`，清单/主档案同步） |

`start` 是 `<group>/<level>/<id>`。常规分组是 `freeRoam` / `races`（`id` 即起点 id）；旧版按车辆库是
`vehicles/<车辆>/library`（id 固定 `library`，例如 `start=vehicles/vivace/library`）——它直接对应
`lapLogs/vehicles/vivace/` 这个目录，没有 `starts/<id>/` 那一层。

### 加新采样参数时改哪里

模组侧三处（照 format 4 的四个载荷 + 两个姿态列的加法抄即可）：

1. `LapLog/lua/vehicle/controller/lapLog.lua`：抬 `FORMAT_VERSION`、追加列号常量、把列号加进 `replayCodec.new` 的
   `indexes`；采样处把值塞进传给 `captureSample` 的那个表。
2. `LapLog/lua/vehicle/lapLog/replayCodec.lua`：`captureSample` 写列（**尾部追加**，旧档案照旧可读）、
   `normalizeReplay` 读列并在 `metadata` 上给出 `hasXxx` 标记。
3. 查看器 `LapLog_Viewer/server.py` 顶部 **`CHANNEL_TABLE`** 加一行 `(列号, 通道 id, 中文名, 单位, 换算系数)`，
   并把通道 id 加进 `SERVE_CHANNELS`。`build_channels()` 会按样本真实列数给每个通道标 `available`，
   旧档案自动留空。

前端曲线面板目前是固定的（`LapLog_Viewer/web/index.html` 里的 `<section class="card">` + `app.js` 的
`charts.*` / `renderCharts`），新开一档曲线要在 `app.js` 里加一段 `setData`（参考 `loads` / `attitude`），
不是"只改 CHANNEL_TABLE"就自动多一条。

**纯查看器侧的派生量**（不需要模组改样本）走另一条路：在 `build_channels()` 里算好、把 id 加进
`DERIVED_CHANNELS` 与 `labels`，前端就能用（现有：航向、距离、纵向加速度、横向 G、**地形坡度 `grade`、
俯仰去地形 `pitch_road`**）。这类改动**必须同时抬 `server.py` 的 `VIEWER_CODE_VERSION` 与 `web/app.js`
的 `SERVER_CODE`**（见上文的重启提示），否则用户只刷新浏览器会看到"新前端 + 旧接口"。

悬架示意（`web/suspension.js`）不是曲线，读的是 `app.js` 的 `suspensionFrame()` 组装的 frame 对象：
新增一个要在示意里体现的字段时，改那里 + `suspension.js` 的绘制，而不是碰 CHANNEL_TABLE。

### 与圈速榜站点的关系

- `Lap_Time_Leaderboard/`（GitHub Pages + 本地 `server.py`，端口 8000）用于**提交/展示成绩**；
- 本分析台（端口 8010）用于**分析自己的圈速存档**，两者互不依赖，可同时运行。
